# 運維設計與開發階段（v1 定案，2026-10-11）

## 1. 排程（台灣時間；GAS 時間觸發器會在指定小時內的某一分鐘執行）
| 排程 | 時間 | 內容 |
|---|---|---|
| 每日輕量 | 每天 22:00–23:00 | 抓當日重大訊息（上市＋上櫃）→ 寫入 raw；檢查「每週主排程是否超過 8 天沒成功」，是則寄告警 |
| 每週主排程 | 每週一 05:00–06:00 | 新聞 RSS、就業通、ESG、AWS 客戶案例 → 清理 → 公司對應 → 訊號 → 計分 → Tier → 預生成 Tier 1 Copilot 內容 → 更新 API 快照 → 寄每週摘要信（週一早上收到） |
| 每月 | 每月 12 日 05:00–06:00 | 公司主檔、月營收（上市櫃公司月營收於每月 10 日前公布）|

## 2. 每週主排程的步驟與失敗處理
```
fetch_news → fetch_jobs → fetch_esg → fetch_aws_cases     （各來源獨立；單一來源失敗不中斷其他來源）
   → normalize → match_company → build_signals
   → score（寫入 scores_staging）→ 全部完成才切換 current_run_id   （不發布算到一半的分數）
   → precompute_copilot（Tier 1、資料版本有變者）
   → write_api_snapshot → send_weekly_digest
```
- **6 分鐘上限**：每個步驟分批處理，進度記錄在 Script Properties；時間快到時自動排一個 1 分鐘後的接續觸發器，從斷點繼續。
- **網路錯誤**：同一請求最多重試 2 次（間隔 2 秒、8 秒），仍失敗則記錄並跳過該筆。
- **單一來源失敗**：其他來源照跑；計分照算（缺資料不算 0 分機制）；資料狀態頁標示該來源「資料過期」；摘要信列出錯誤。
- **計分或發布步驟失敗**：不切換 current_run_id，網站繼續顯示上週結果；立即寄失敗通知。

## 3. 冪等性（重跑不出事）
- 每次執行有 run_id（例：`2026-W42`、`2026-10-12-daily`）
- raw 資料以「來源＋原始 ID（或內容雜湊）」去重，重跑不會重複寫入
- 訊號以 signal_id upsert；分數以 run_id 為鍵
- 摘要信、告警信寄出前檢查「此 run_id 是否已寄」

## 4. 紀錄與監控
- Sheets `run_log`：run_id、步驟、開始/結束時間、處理筆數、狀態、錯誤訊息
- Sheets `ai_log`：見 Step 2
- 資料狀態頁讀取 run_log：各來源最後成功時間、筆數、錯誤

## 5. 秘密與安全
- Script Properties 存放：`GEMINI_API_KEY`、`LIVE_PASSCODE`、`ALERT_EMAIL`（不寫進程式碼，不進 GitHub）
- GitHub Pages 免費方案需要公開 repo → repo 內不可有金鑰、Email、Sheets ID 以外的敏感資訊；README 說明如何自行設定 Script Properties
- GAS Web App 部署為「任何人可存取」（前端才能讀取），API 只回傳由公開資料計算出的結果
- 即時模式：通行碼驗證＋每日次數上限

## 6. 已知技術地雷（交給 Claude Code 時要特別標註）
- **GAS Web App 跨網域**：前端用簡單 GET 讀資料；POST 請用 `Content-Type: text/plain` 送 JSON，避免觸發瀏覽器預檢請求（GAS 不處理 OPTIONS）。需在 Phase 0 實測確認。
- **海外連線**：GAS 在 Google 海外伺服器執行，台灣政府網站可能擋海外 IP → Phase 0 先測。
- **Gemini 免費額度**：Google 不再公開固定數字，以 AI Studio 專案頁面顯示為準；模型名稱放設定，不寫死。
